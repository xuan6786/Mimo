# 2026-09-22

## 项目初始化：MiMo 本地助手

在 `Y:\A_MiMo` 从零搭建了一个本地调用小米 MiMo API 的命令行对话助手。

### 交付物
- `mimo_client.py`（419 行）：MiMo API 客户端，纯标准库实现（urllib + json + socket），
  兼容 OpenAI Chat Completions 协议，支持 SSE 流式解析、`reasoning_content` 提取、
  指数退避重试、超时、代理。可独立当 SDK 用（`ask()` / `MiMoClient.chat()`）。
- `assistant.py`（773 行）：CLI 主程序。流式打字机输出、思考过程着色、20+ 条斜杠命令
  （/model /system /set /retry /undo /save /load /usage 等）、会话存档到 `sessions/`。
- `config.json`：api_key / base_url / model / params / extra_body 等配置。
- `启动助手.bat`：Windows 一键启动（含 chcp 65001）。
- `README.md`：完整中文文档。

### 关键技术决策
1. **零第三方依赖**：不用 openai SDK，直接 urllib 手写 SSE 解析，用户无需 pip install。
2. **鉴权头同时发**：`api-key: xxx` 与 `Authorization: Bearer xxx` 都带上（官方两种都支持）。
3. **未知参数走 extra_body 透传**：`/set` 命令中非标准采样参数的键会原样透传给接口，
   这样无需硬编码就能用联网搜索等特性（如 `/set forced_search=true`）。
4. **失败时撤回 user 消息**：避免失败请求污染上下文，内容暂存到 `pending_user` 供 `/retry`。

### 已验证（用本地 mock SSE 服务端离线测试）
流式 / 非流式 / 自检 / 命令交互 / 撤销 / 存档 / 重试 / 错误提示，全部通过。

### MiMo API 关键事实（来自官方文档）
- 按量付费 base_url：`https://api.xiaomimimo.com/v1`，Key 格式 `sk-xxxxx`
- Token Plan base_url：`https://token-plan-cn.xiaomimimo.com/v1`，Key 格式 `tp-xxxxx` / `ttp-xxxxx`
- 批量推理：`https://batch-api-cn.xiaomimimo.com/v1`
- 模型：mimo-v2.6-pro / mimo-v2.6-pro-ultraspeed / mimo-v2.6-flash / mimo-v2.5-pro / mimo-v2.5
- 思考模式下 temperature、top_p 被强制为 1.0 / 0.95
- V2.5 系列 2026-10-21 下线

### 踩坑记录
- **同一文件并行 Edit 会互相覆盖**：两个 Edit 调用同时发往 `assistant.py`，
  第一个改动被第二个覆盖丢失，且工具仍报 success。教训：同一文件的多处修改必须串行执行，
  改完要 Read/Grep 复核。

## 追加：网页版可视化界面

给助手加了一套本地网页聊天界面（同样零第三方依赖）。

### 新增文件
- `server.py`（~430 行）：本地 HTTP 服务。静态托管 `web/`；`/api/chat` 把浏览器请求
  代理到 MiMo 并以 SSE 流式回推（自定义事件 `start/reasoning/content/usage/retry/done/error/end`）；
  `/api/config` 读写 config.json（字段白名单）；`/api/test` 连通性自检；`/api/models` 拉模型列表。
  默认只监听 127.0.0.1。流式响应用 `Connection: close` 关闭连接来界定结束，不做 chunked 编码。
- `web/index.html` + `web/style.css` + `web/app.js`：原生 HTML/CSS/JS 单页应用。
  浅色/深色双主题（橙色强调色）、多会话 localStorage 持久化、流式打字机、
  自研 Markdown 渲染（标题/列表含嵌套/表格/引用/代码块/链接/转义安全）、
  自研代码高亮（关键字/字符串/注释/数字，先分词再转义，避免破坏 HTML）、
  思考过程可折叠区块、停止生成、重新生成、导出 Markdown。
- `启动网页版.bat`：Windows 一键启动。

### 关键设计决策
1. **SSE 转发而非 WebSocket**：单向流足够，用 fetch + ReadableStream 读，AbortController 中断。
2. **高亮先分词后转义**：早期想法是先 escapeHtml 再正则，但 `"` 会变成 `&quot;` 导致字符串
   规则失效。改为在原始代码上跑正则，逐段转义后拼接。
3. **Markdown 代码块先抽占位符**：`\u0000BLOCKn\u0000` 占位，行解析时整行命中即还原为代码块。
4. **列表用带 li 标志的层级栈**：支持嵌套列表且保证标签配对。
5. **服务复用 assistant.py 的 load_config/save_config/mask_key**，避免配置逻辑重复。

### 验证方式（无法用浏览器，改用可编程验证）
- 本地 mock SSE 上游 + curl：静态资源、/api/config、/api/test、/api/chat 全部通过
- node `--check` 校验 app.js 语法
- node `vm` 沙箱加载 app.js 单测 Markdown 渲染 8 个用例：标签配对、HTML 转义、无残留占位符，全通过
